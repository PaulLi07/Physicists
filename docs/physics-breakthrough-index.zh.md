# 物理学突破指数：计算与维护说明

版本：3.0。更新日期：2026-10-27。英文对应文档：[Calculation and maintenance](physics-breakthrough-index.en.md)。

## 1. 指标与记账单位

指数描述本档案库收录的物理学成果在历史时间中的分布，兼顾成果数量与重要程度。记账单位是**一项可明确描述的成果**，包括理论、实验发现、观测资料、测量体系、仪器方法和具有实质物理内容的系统整理。人物是成果的关联参与者，不是计分单位；作者数、论文篇数、人物寿命、获奖次数和网页访问量不直接增加分数。

本指标使用项目统一的编辑评估等级。期刊、原始文献和历史机构资料支持成果事实、日期与归属；它们不提供本项目的“官方评分”。评分理由和版本保存在数据中，便于后续逐项修订。

三个时间概念必须分开：

- **成果时间**：决定年度指数，依照提出、完成、首次公开报告或发现的证据确定。
- **人物导航时间**：每人选一项代表成果定位目录；没有可用成果日期时可估计活动期，仅用于人物导航与密度展示。
- **生卒日期**：属于人物档案，不代替成果时间。

例如，1964年的质量生成机制和2012年的希格斯玻色子发现分别记入1964年和2012年。2013年的诺贝尔奖不把这两项成果移到2013年，也不自动产生第三份成果分数。

## 2. 不同历史时期的评估路径

`assessment.route` 有三种取值。路线用于选择合适的评价证据，不是年代加成系数；同等物理意义的成果使用同一等级尺度，跨路线没有突然跳变的乘数。

| 路线 | 适用材料与评价重点 |
| --- | --- |
| `historical` | 古代至早期近代：著作、手稿、观测记录、可靠历史研究。重建概念、定量关系、实验传统、观测资料和知识系统化等贡献单元；不以缺少现代论文、DOI或引文数降低重要性。 |
| `classical` | 经典物理形成与发展：原始著作、学会报告、实验与仪器记录。评价定量规律、数学统一、精密测量和可重复实验建立的能力。 |
| `modern` | 近现代：原始论文、合作组报告、实验机构资料、期刊里程碑。区分理论提出、实验发现、关键验证和可复用方法；不把论文数量或合作人数当作成果规模。 |

路线按成果的历史环境与证据性质选择，不把某个公历年份当成所有学科共同的突变边界。早期贡献可以由编辑直接评估，只需把**具体做成了什么**、日期依据与评分理由写入成果记录。例如，第谷的高精度行星观测资料应作为数据与测量贡献评估，而不是用第谷个人的一个小残余因子替代。

历史命名要准确区分：哥白尼日心体系的早期提出采用1502—1514年编辑形成区间；约1510是常见估年，1514为已有手稿流传的记录上限。1543年完整《天体运行论》的出版另存为传播元数据，不再重复计分。开普勒的行星运动定律分别建项。前两定律于1609年出版，第三定律于1619年出版而在1618年形成；实际计分采用各记录的形成区间或形成年度，不能把它们合称为开普勒“提出日心说”。

## 3. 重要性等级

`score` 只使用 `1、2、4、8、16` 五档；兼容字段 `weight` 必须与其相同。档位表示成果总预算，不是每位作者或每年的预算。

| 分数 | 校准含义 |
| ---: | --- |
| 1 | 有清楚物理内容的增量推进、局部测量或方法改进。 |
| 2 | 重要的独立结果，明显改善某问题的理解或实验能力。 |
| 4 | 一个研究方向的重大进展，建立重要现象、定量规律或可广泛使用的方法。 |
| 8 | 分支奠基或重大跨领域贡献，形成持久的理论、实验或观测能力。 |
| 16 | 改变基础框架或统一范围极广的贡献；牛顿1687年运动定律与万有引力体系是最高档校准锚点之一。 |

评估同时考虑概念新颖性、定量解释与预测能力、实证或测量能力、适用范围及后续影响。它们用于写出可审查的理由，不机械相乘，也不把多个小项目拼成分数竞赛。长期观测、仪器方法和理论统一均可达到高档，具体档位以该成果记录的 `assessment.rationale` 为准。

`assessment.confidence` 为 `high / medium / low`，表示编辑对当前档位判断的把握程度，不是概率，也不是科学理论为真的概率。日期证据可另以 `dateConfidence` 记录。**重要性、评分把握和日期精度分别保存**；史料稀少不自动等于低分，日期宽也不降低成果总预算。

## 4. 成果日期与年度分配

`dateModel` 优先于旧的 `year / dateRange` 字段。`basis` 记录使用的日期依据；原始日期可由构建器保留在 `sourceDate` 中。历史纪年使用负数表示公元前，前1年之后直接是公元1年，没有历史0年。

日期选择依次优先有据的实际观测或形成时间、已定年的研究手稿或预印本、最早可核实公开记录；仍无法定年时使用具名编辑估计区间。`basis` 推荐使用 `observation / achieved / documented-manuscript / first-public-record / editorial-interval`，并单独保存 `timelineDates`。期刊收稿记录只证明成果**至迟已经形成**，若采用该稿件年份为定位锚点，使用 `documented-manuscript` 和 `dateConfidence: "documented-upper-bound"`，记录 `received / published` 并解释界限，不能宣称确知发现或思考完成时刻。`dateConfidence` 的其他常见值是 `documented / approximate-source / estimated / undated`；它不决定重要性分数。

### 4.1 单年事件：`point`

```json
{"kind":"point","basis":"first-public-record","start":1964,"end":1964}
```

总预算全部记在该年。明确的发表、报告或发现年不能因人物代表贡献年而改变，也不按时代向前后扩散。若来源本身只给出“约某年”，保留 `precision: "approximate"`，不能仅因 `start === end` 就声称定年精确。

### 4.2 日期不确定：`uncertain-range`

```json
{"kind":"uncertain-range","basis":"historical-interval","start":-310,"end":-290}
```

在给定区间的有效历史年份间均分一个总预算。该模型表示成果时间不确定，不表示在每一年都独立完成一次成果。区间必须有生平、文本、史料或编辑估计依据，并在 `dateNote` 说明；不能用任意宽窗口把已知单年成果摊薄。

### 4.3 持续工作：`sustained`

```json
{
  "kind":"sustained","basis":"documented-work-period","start":1576,"end":1601,
  "allocations":[
    {"start":1576,"end":1585,"fraction":0.25},
    {"start":1592,"end":1601,"fraction":0.75}
  ]
}
```

此示例仅演示格式，不是第谷观测资料的历史评分结论。各阶段使用 `fraction` 分摊**同一个**成果总预算，再在阶段内部按年均分。份额总和必须为1；阶段不得重叠、超出总区间或包含0年端点。可以保留实际未分配的工作间隔。若没有可靠的阶段划分，省略 `allocations`，在整个持续区间均分一个预算。任何阶段都不能再次获得完整总分。

### 4.4 原始年度公式

设成果总分为 `S_e`，年度份额为 `p_e(y)`：

```text
I(y) = Σ_e S_e × p_e(y)
Σ_y p_e(y) = 1
Σ_y I(y) = Σ_e S_e
```

只对可计分且有日期的成果求和。`indexEligible: false` 的历史记录保留在库中，但不增加指数；`supersedes` 替换的旧记录同样退出计分。未知日期记录不凭空获得年份，须补充有依据的日期模型或具名编辑估计事件。

v3的输出 `raw` 与 `value` 相同，没有历史年代平滑核，也没有最近几年向未来扩散后造成的自动衰减。增加一项正分成果或提高某项分数，不会压低其他年份的原始指数。

## 5. 独立成果、共享成果与编辑估计

一项成果有多个参与者或多篇共同确认论文时，保留一个成果预算。同期不同团队形成同一核心机制的论文可共同支持一条记录；独立理论提出与后来的实验发现可分为两项，分别按实际年份记账。不同仪器、重复测量或同一结果的后续论文，只有形成可清楚说明的新物理贡献才另立事件。

`eventFamilyId` 将有关联的贡献归在同一问题族；它不代表同族记录自动互斥，编辑仍须审查它们是否分别提供新内容。合并、替换或重新划分时使用稳定ID与 `supersedes`，保留旧记录及替换关系。

能够确认贡献内容但难以直接量化者，建立具名成果事件，并使用：

```json
{
  "assessment":{
    "basis":"editorial-estimate","route":"historical",
    "rationale":{"zh":"具体评估依据","en":"Specific assessment rationale"},
    "confidence":"medium","version":"3.0"
  },
  "sourceEstimate":true
}
```

一般文献成果的 `basis` 使用 `editorial-review`。所有分数都是编辑评估；两种basis区分的是贡献记录是否依赖额外的编辑重建，不把编辑估计伪装成期刊原文。估计记录仍需要引用实际使用的材料，不捏造论文、DOI或精确日期。

已退役的v2个人残余评分不得与具名事件叠加。`navigationEstimates` 仍可保存人物活动期与导航估年，但不会向指数添加任何分数。未来找到更好证据时，更新或替换原事件，而不是把同一贡献再计一次。

输出分别保存 `rawObserved / observed` 和 `rawEstimated / estimated`。前者是 `editorial-review` 成果分量，后者是 `editorial-estimate` 成果分量；这里的“observed”不是“仅实验结果”的意思。`uncertain` 汇总编辑估计及日期不确定分量，不解释为统计误差带。

## 6. 人物目录与密度颜色

目录每人只显示一次。导航锚点优先选择定年更明确的成果，其次比较分数，再比较较早年份；区间锚点取历史连续纪年的中点。同年人物沿用档案顺序。`sourceEstimate: true`、编辑估计及约年定位保留相应估计标记。该导航规则不会改变其他成果的年度归属。

人物密度独立于成果重要性。使用11年窗口：

1. 对一项成果，计算窗口覆盖的年度份额；持续工作按各阶段 `fraction × 覆盖年数 / 阶段年数` 相加。
2. 对同一人物的多项成果，取最大覆盖份额，避免一人被算成多人。
3. 导航估计区间按均分份额参与同样的去重，但不参与成果分数。
4. 所有人物份额相加得到 `people`；`density = people / 11`。

它表示档案支持的贡献人物年代分布，不是年度物理学从业人口。直方图填色按全库最大密度归一后，严格使用ROOT给定节点的RGB线性插值：

| 归一化密度 | RGB |
| ---: | --- |
| 0 | (0.9, 0.9, 0.9) |
| 0.25 | (0.15, 0.15, 0.15) |
| 1 | (1, 0, 0) |

没有平方根或gamma变换；bin紧邻、无边线。此填色与成果文字的重要性颜色是两个独立编码。

## 7. 图形尺度与成果文字

数据库保存线性年度值。为同时看清古代稀疏成果和现代较高峰值，横向图形采用已标明的asinh显示变换：

```text
width(I) = W × asinh(I / k) / asinh(M / k)
k = 1
```

`M` 为图形横轴上限，`W` 为可用宽度；刻度标签仍显示原始指数值。变换保持零点、顺序与单调性，不修改分数，不分别把各时代峰值归一到同样高度。

屏幕每个纵向像素可能覆盖多个年份，显示其**按年份区间重叠加权的年度均值**，不是把压缩区间的所有分数相加。年度值视为以该年为中心的单位宽单元；公元前后换算不引入0年单元，相邻像素不会把共同边界上的整年重复计入。垂直时间轴分段线性，各段有断点标记；段内使用线性年份映射。

主页面右侧直接展示成果标题及必要年份，不展示分数、权重或“点／年”。 年度卡先按总分排序，同档优先当年单年成果；人物悬停卡优先展示其最高重要性成果，独立于目录导航锚点。标题颜色只由该成果的**总分等级**确定，不由某年分摊量、作者数、人物密度或当前筛选结果决定：

| 总分 | 文字颜色 |
| ---: | --- |
| 1 | `#414146` |
| 2 | `#704047` |
| 4 | `#a63843` |
| 8 | `#c72b3b` |
| 16 | `#df2434` |

## 8. 数据文件与构建顺序

源文件在 `data/breakthrough/`：

- `events-*.json`：具名成果及原始来源，包括编辑评估事件。
- `existing-source-patches.json`：既有成果的来源增补。
- `event-assessments.json`：v3分数、评估路线、理由和日期模型补丁。
- `editorial-event-patches.json`：具名编辑补充与修订。
- `index-config.json`：评估版本、日期及显示参数。
- `journal-sources.json`：实际使用的期刊精选集合。

构建器依次读取成果、应用来源补丁、评估补丁、编辑补丁，再处理替换关系、验证、生成导航与计算年度账本。`score / weight` 保持镜像。人物档案来自 `website/dist/data/archive.js`，成果的 `people` 必须引用已存在人物ID。

主要生成文件为 `yearly-index.json`、`navigation-estimates.json`、`coverage.json`、`sensitivity.json` 以及 `website/design-review/data/` 下的浏览器数据与方法文档副本。`contribution-estimates.json` 在v3仅保留退役标记和空记录。不要直接编辑生成文件。

## 9. 新增与修订步骤

1. 查找已有事件与问题族，明确此次补充是新成果、来源增补还是旧条目的替换，先排除重复计分。
2. 核对事实、参与者与实际成果日期；分别提供中英文标题、贡献说明、日期说明和真实来源。
3. 选择历史评估路线，确定五档总分，写明理由与评分把握；日期不确定时单独记录日期依据。
4. 设置 `eventFamilyId`、`assessment.version` 与日期模型；持续工作核对各阶段预算。必要时填写 `supersedes`。
5. 若新增人物，先更新中英文人物档案并重建人物数据；已有参与者使用稳定ID。
6. 在项目根目录运行：

```bash
python3 scripts/build_website.py
node scripts/build_breakthrough.cjs
node --test website/design-review/tests/*.test.cjs
python3 website/serve.py --design-review
```

仅调整成果库时可省略第一条。预览入口为 `website/design-review/preview.command`；预览服务在启动和刷新首页时检查输入变化并重算。

核查年度总和等于全部可计分事件预算之和；1964/2012等分离案例正确；未知日期不会凭空记账，0年、未来年份与阶段重复预算被拒绝；人物导航覆盖完整；中英文成果标题、日期与方法文档一致。浏览器复核成果颜色、时间轴拖拽与正文同步。敏感性输出比较主尺度 `1/2/4/8/16` 与替代尺度 `1/2/4/6/8`，不改变日期或成果划分。

## 10. v2到v3的迁移与后续版本

v3取消按人物生成的残余分与按年代变化的三角平滑。具名贡献通过 `event-assessments.json` 或新事件升级为事件预算，原始日期与来源保留；人物估年迁到导航用途。年度账本统一以 `raw === value` 输出，asinh只在显示时应用。

修改分数、日期或事件边界时，应同时更新该事件的评估理由、版本或修订记录，并重新生成全部输出；涉及共同规则改变时同步修改本中英文文档与测试。保留稳定事件ID、旧来源与替换关系，提交可审查的Git变更。方法版本与统计截止日期分别管理，不能仅因预览或重建就把历史记录改成“新成果”。
